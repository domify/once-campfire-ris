# Golden vectors

JSON files generated by the reference app (`reference/`, Rails main, `load_defaults 8.2`) running in
production mode inside the `campfire-reference` image. Tests in the Rust crates read them; never
edit them by hand.

They use the fixed `SECRET_KEY_BASE` from `parity/.env.reference` (recorded in each file as
`secret_key_base`). A second secret, `rotated_secret_key_base`, stands in for a rotated
`SECRET_KEY_BASE` in the "wrong secret" cases. The clock is frozen at `now` (2026-01-01T12:00:00Z).

## Regenerating

    reference-tools/run.sh reference-tools/rails_compat_vectors.rb      # writes vectors/rails_compat.json
    CARGO_TARGET_DIR=target/rails_compat cargo test -p rails_compat     # also writes target/rails_compat_rust_output.json
    reference-tools/run.sh reference-tools/rails_compat_verify_rust.rb  # Rails verifies what Rust generated
    reference-tools/run.sh reference-tools/ruby_core.rb                 # writes vectors/ruby_core.json

`run.sh` uses the `campfire-reference` Docker image (the oracle). With `REFERENCE_NATIVE=1`, or
without Docker, it runs the local Ruby (see `reference/.ruby-version`) with the same bundle
installed into `target/reference-bundle`:

    cd reference && BUNDLE_PATH=../target/reference-bundle BUNDLE_WITHOUT=development:test bundle install

## assets/

What the reference's `assets:precompile` and its Rails helpers produced, copied from the Rust
port's `crates/assets/tests/reference/` (written there by `script/revendor`): `manifest.json`,
`stylesheet_link_tag_all.html`, `link_header.txt` and `javascript_importmap_tags.html`. Files in
`rils/assets/overrides/` digest differently on purpose; `rils/assets/pipeline_test.ri` maps those names
back before comparing.

## views/

Pages the reference app rendered (`reference-tools/views/a/render.rb`), copied from the Rust
port's `crates/views/tests/golden/a/`: `sessions_new*.html`, `incompatible_browser.html`, `first_run.html` and `welcome.html` (and the other pages), the
non-HTML renders (`avatar_*.svg`, `manifest.json`, `service_worker.js`, `user_json.json`,
`autocompletable_users_json.json`), and `facts.json`, the
part of its `facts.json` those cases were rendered with (asset paths and tags, the account, the
help contact, the current user). The views tests compare byte for byte, after taking out the
`csrf_meta_tags` and `authenticity_token` fields Rails renders and this app doesn't.

## views_b/

The Rust port's `crates/views/tests/golden/b/` (written by `reference-tools/views/b/run.sh`):
each page as the canonical token stream `reference-tools/views/b/canonical.rb` makes of the
reference's render, with the request's context and the view model it was rendered from.
`test/views/dom.ri` tokenizes ours the same way; `test/views/golden_b.ri` compares region by region.

## richtext/

The Rust port's `crates/richtext/tests/corpus/expected.json` (written by
`reference-tools/richtext/run.sh` from the real Rails pipeline): 658 stored message bodies with
their presentation, plain text, editor value and mentions. `rils/richtext/richtext_test.ri` runs them
through the pipeline, with the port's deliberate differences, all exact.
